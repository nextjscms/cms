# Theme Development Rules

## Styling and Colors
When building or modifying themes for NextjsCMS, theme developers MUST bridge dynamic database styling and hardcoded CSS using CSS Variables in the Tailwind configuration.

Do NOT hardcode specific colors (e.g., `bg-blue-500`) if that element is intended to be controlled by the theme customizer. Instead:
1. Define the CSS Variables generated by the CMS (e.g., `--primaryColor`) in the theme's `tailwind.config.ts`.
2. Map these variables to standard Tailwind classes:
   ```typescript
   module.exports = {
     theme: {
       extend: {
         colors: {
           primary: 'var(--primaryColor, #2563eb)', 
           surface: 'var(--surfaceColor, #ffffff)',
         }
       }
     }
   }
   ```
3. Use the resulting Tailwind classes (e.g., `bg-primary`, `text-primary`) in your React components.

**For Non-Tailwind Themes (Vanilla CSS, CSS Modules, etc.):**
If a theme does not use Tailwind CSS, developers must still rely on the injected CSS variables for any dynamic styling.
1. Do NOT hardcode colors in your `.css` files (e.g., `background-color: #2563eb;`).
2. Use the CSS `var()` function to consume the CMS variables, providing a fallback value matching the theme's default design:
   ```css
   .btn-primary {
     background-color: var(--primaryColor, #2563eb);
     color: var(--surfaceColor, #ffffff);
   }
   ```
3. Use these standard CSS classes in your React components.

These practices ensure zero specificity conflicts between the developer's styling and the user's database settings, and allow full compatibility with dynamic Live Preview in the CMS Customizer.
